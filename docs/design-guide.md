# Checky 디자인 가이드

앱 화면을 추가하거나 수정할 때 먼저 이 문서와 `apps/mobile/lib/design_system/`의 토큰을 확인한다. 화면마다 새로운 글자 크기와 색상을 만들지 않고 같은 역할에 같은 스타일을 사용한다.

## 테마와 색상

- 화면 설정에서 `민트`, `크림`, `라벤더`, `로즈`, `스노우`를 선택한다. 기본값은 민트다. 로즈는 부드러운 핑크, 스노우는 화이트·중성 회색 계열이다.
- 화면 모드 `시스템 / 라이트 / 다크`는 테마와 독립적이다. 모든 테마는 밝고 어두운 팔레트를 제공한다.
- 설정은 기기에 보관하고 앱 재실행 후 복원한다. 그룹 구성원의 화면 설정을 바꾸지 않는다.
- 원본 팔레트는 `app_theme_preset.dart` 한 곳에서 관리한다. 기본 배경, 카드, 강조색뿐 아니라 글자와 테두리도 함께 선택된다.

| 토큰 | 용도 |
| --- | --- |
| `background` | 화면 배경 |
| `surface` | 카드, 입력 영역 |
| `surfaceElevated` | 보조 영역, 비선택 컨트롤 배경 |
| `primary`, `primarySoft` | 주요 액션, 선택 상태, 옅은 강조 배경 |
| `onPrimary` | primary 배경 위의 글자와 아이콘 |
| `textPrimary` | 제목, 본문, 입력값 |
| `textSecondary` | 설명, 날짜·시간 |
| `textMuted` | 보조 정보, 빈 상태 |
| `border` | 카드 경계, 구분선 |
| `success`, `warning`, `danger` | 완료, 주의, 삭제·실패 |

새 위젯의 `build`에서는 `final colors = AppColors.of(context);`로 현재 팔레트를 가져온다. 이 호출은 테마 의존성도 등록하므로 열린 상세 화면과 바텀시트도 테마 변경을 반영한다. 기존 화면의 정적 `AppColors` 접근을 유지할 때도 `build`에서 `AppColors.of(context)`를 호출한다. 화면에서 전역 팔레트나 밝기를 직접 바꾸지 않는다.

구성원 구분색, 공휴일 빨강, 카카오 로그인 브랜드 색상은 의미가 있으므로 테마와 독립적으로 유지한다. 쿠폰 원본 이미지 배경과 사진 뷰어의 검정 배경도 예외다. 선택 상태는 색 외에 체크 아이콘 등으로도 구분한다. 강조 배경에 흰 글씨를 고정하지 말고 `onPrimary`를 사용한다.

일반 텍스트는 배경과 최소 4.5:1 대비를 유지한다. 팔레트 변경 시 `theme_settings_test.dart`의 대비 검증과 밝고 어두운 화면을 확인한다.

## 타이포그래피

화면 설정 → 글꼴에서 기본·고운돋움·고운바탕·온글잎 박다현체·푸어스토리·인천교육힘찬체를 선택한다. 색상 테마와 별도로 기기에 저장하고 즉시 적용한다. 기본은 플랫폼 기본 글꼴이다. 사용자 선택은 앱 내부 제목·본문·버튼·입력·피커와 iOS·Android 홈 위젯에 공통 적용하며, 각 글꼴의 한글·영문 미리보기를 제공한다. 기존 아인맘 선택값은 온글잎 박다현체로 이어지고, 그 외 제외된 글꼴의 저장값은 기본 글꼴로 복원한다.

글꼴은 앱의 `assets/fonts/`에 원본 TTF와 각 글꼴의 라이선스를 함께 포함한다. 고운돋움·고운바탕·푸어스토리는 OFL, 온글잎 박다현체는 온글잎 오리지널 폰트 라이선스, 인천교육힘찬체는 공식 배포처 사용조건을 적용한다. 비-OFL 글꼴의 파일은 수정·변환·서브셋하지 않는다. 실행 중 네트워크로 내려받거나 별도 폰트 패키지를 추가하지 않는다. 출처와 버전은 `assets/fonts/README.md`, 이용조건은 글꼴 화면의 라이선스 링크에서 확인한다. 미지원 문자는 플랫폼 기본 글꼴로 폴백하며, 입력 내용에 맞춰 한글 파일을 임의로 서브셋하지 않는다.

모든 텍스트는 `AppTypography` 토큰을 사용하고 화면 파일에서 `fontSize`, `fontWeight`, `letterSpacing`을 직접 지정하지 않는다. 글꼴은 앱 테마에서 상속한다. 개별 스타일에 `inherit: false`를 넣어 선택 글꼴 상속을 끊지 않는다. 글꼴 미리보기와 라이선스 원문의 기본 글꼴 표시는 `AppFontPreset.applyTo(...)`를 사용하는 예외다. 필요한 차이는 색상, 정렬, 줄 수로 표현한다.

| 토큰 | 크기 / 굵기 | 역할 |
| --- | --- | --- |
| `display` | 32 / 700 | 브랜드, 드물게 쓰는 큰 요약 |
| `titleLarge` | 24 / 700 | 화면 내부의 대표 제목 |
| `titleMedium` | 20 / 600 | 주요 섹션 제목 |
| `titleSmall` | 17 / 600 | 내비게이션 제목, 주요 목록 제목 |
| `bodyLarge` | 17 / 400 | 읽기 중심 상세 본문 |
| `bodyMedium` | 15 / 400 | 기본 본문, 입력값 |
| `bodySmall` | 13 / 400 | 설명, 날짜·시간 |
| `caption` | 12 / 500 | 작성자, 상태, 보조 메타 정보 |
| `label` | 15 / 600 | 폼 라벨, 강조된 짧은 값 |
| `labelSmall` | 13 / 600 | 필터, 태그, 짧은 액션 |
| `button` | 16 / 600 | 주요 버튼 |
| `calendar` | 10 / 600 | 촘촘한 캘린더 셀, N 배지에만 사용 |

제목과 라벨 외에는 굵은 글씨를 남용하지 않는다. 문단은 `bodyLarge`나 `bodyMedium`의 줄간격을 그대로 사용한다. 목록 제목은 한두 줄, 보조 정보는 한 줄을 기본으로 하며 긴 한국어는 `Flexible`/`Expanded`와 `ellipsis`로 처리한다. 필수 정보가 사라지는 고정 높이와 텍스트 배율 강제 고정을 피한다.

```dart
final colors = AppColors.of(context);
Text(
  title,
  maxLines: 2,
  overflow: TextOverflow.ellipsis,
  style: AppTypography.titleSmall.copyWith(color: colors.textPrimary),
);
```

## 간격, 모서리, 터치 영역

- 간격은 `AppSpacing`: 4, 8, 12, 16, 20, 24, 32, 48을 사용한다.
- 화면 좌우 여백은 `page` 20, 카드 안쪽은 `lg` 16, 섹션 간은 `xl` 24 또는 `xxl` 32다.
- 제목과 설명은 8, 목록 항목 간은 12, 연관된 작은 요소는 4 간격을 기준으로 한다.
- 모서리는 `AppRadius`: 안쪽 요소 8, 기본 카드·입력 영역 12, 큰 카드 16, 시트 상단 24, 필터·태그는 pill이다.
- 기본 경계선은 1, 선택 테두리는 2다. 그림자와 카드 중첩은 최소화한다.
- 액션 터치 영역은 최소 44×44, 주요 제출 버튼은 높이 48을 기준으로 한다. 작은 아이콘에도 충분한 패딩을 둔다.
- 캘린더·시간 입력처럼 밀도가 필요한 곳은 2~6 간격과 작은 모서리를 허용한다. 캘린더의 글자 크기를 바꾸면 슬롯 높이도 함께 확인한다.

## 화면과 상태

- 화면, 내비게이션, 버튼, 전환, 로딩은 기존 Cupertino 컴포넌트를 우선 사용한다.
- 같은 폼의 라벨·입력값·힌트는 같은 스타일을 쓴다. 주요 제출 버튼은 한 화면에서 명확히 보이게 한다.
- 기본 정보와 추가 액션을 분리하고 삭제 같은 위험 액션은 확인 과정을 유지한다.
- 로딩은 `CupertinoActivityIndicator`, 빈 상태는 짧은 제목과 필요한 액션, 오류는 재시도 방법을 제공한다.
- 조회 갱신 시 탭·스크롤·입력을 유지한다. 테마 변경을 이유로 페이지를 재생성하거나 로그인 흐름을 초기화하지 않는다.
- 네이티브 홈 위젯은 앱의 테마·화면 모드·글꼴을 공유한다. `HomeWidgetService.updateAppearance`가 밝고 어두운 팔레트와 글꼴 저장값을 독립된 `appearance` 값으로 전달하며, 네이티브는 배경에 `primarySoft`, 카드에 `surface`, 제목·본문·보조 정보·구분선에 해당 역할 색상을 사용한다. 구성원 구분색은 유지한다. 데이터 백그라운드 갱신 시 테마와 글꼴을 덮어쓰지 않는다. 공유 확장 테마·글꼴은 앱 설정과 별개다.
- iOS 위젯은 `assets/fonts/` 원본과 라이선스를 확장 리소스로 포함하고 `UIAppFonts` 및 실제 PostScript 이름으로 등록한다. Flutter의 `Checky…` 별칭을 SwiftUI 글꼴 이름으로 사용하지 않는다. 새 글꼴 추가 시 iOS 매핑·등록, Android 매핑, 네이티브 렌더링 테스트를 함께 갱신한다. 라이선스 제한 때문에 위젯용 글꼴도 변환·서브셋하지 않는다.
- Android 사용자 글꼴은 기존 RemoteViews 레이아웃을 앱 프로세스에서 원본 TTF로 그린 후 20만 픽셀(ARGB 약 800KB) 이하 이미지로 전달한다. 외부 런처에 사용자 Typeface/custom span을 직렬화하지 않는다. 접근성 설명·앱 열기 동작을 유지하고 기본 글꼴이나 렌더링 실패 시 기존 TextView 방식으로 복원한다. 작은/넓은 위젯의 일정·주차/한쪽만/빈 상태와 긴 한글·영문을 확인한다.

## 완료 전 확인

1. `dart format lib test tool`, `dart tool/check_design.dart`, `flutter analyze`, `flutter test`를 실행한다.
2. 모든 테마를 라이트·다크로 보고, 글꼴 선택까지 열린 화면에서 즉시 변경되는지와 재실행 후 복원을 확인한다.
3. 좁은 화면(320pt)과 큰 글자(1.3배 이상)에서 제목·버튼·폼·시트가 넘치지 않는지 확인한다.
4. 일정·주차·스크랩·쿠폰·여행의 일반/빈/오류 상태와 긴 이름·제목을 확인한다.
5. 새로운 시각 역할이 필요하면 토큰과 이 문서를 먼저 갱신하고, 예외는 이유를 남긴다.
