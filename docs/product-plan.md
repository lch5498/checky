# 제품 계획

## MVP 목표

그룹 내 반복 일정과 주차 위치를 빠르게 확인하고 기록하는 작은 내부 앱을 만든다. 첫 화면은 복잡한 대시보드 없이 두 개의 큰 메뉴 버튼만 제공한다.

## 화면

### 홈

- `일정 관리` 버튼
- `주차 관리` 버튼

### 반복 일정 관리

- 이번 주 반복 일정 목록
- 일정 추가: 학생 이름, 반복 일정명, 시작 시간, 종료 시간, 메모
- 일정 수정/삭제
- 다음 단계: 반복 일정, 알림, 캘린더 연동

### 주차 관리

- 현재 주차 위치 보기
- 주차 위치 등록: 차량명, 위치, 주차 시간, 메모
- 이전 주차 기록 보기
- 다음 단계: 사진 첨부, 지도 링크, 위치 공유

## 데이터 모델

- `family_members`: 그룹 구성원
- `academy_events`: 반복 일정
- `parking_records`: 주차 기록

## 기술 방향

- Flutter 앱은 iOS 우선으로 개발한다.
- 앱은 Vercel API만 호출한다.
- Vercel API는 Supabase service role key를 서버에서만 사용한다.
- Supabase Row Level Security는 켜고, 클라이언트 직접 접근은 나중에 인증을 붙일 때 정책을 확장한다.

## 그룹 쿠폰 수용 기준

- 사용자는 하단 스크랩의 `글·링크 | 쿠폰` 탭으로 전환한다. 기존 채널/공유 저장 흐름과 하단 홈·일정·주차·스크랩·여행은 유지한다.
- 현재 그룹에 이미지 한 장과 쿠폰 이름을 등록한다. 유효기간·쿠폰 번호·메모는 선택 입력이다. 번호가 없는 QR 쿠폰도 저장할 수 있다. 사진 선택 시 기기 내 OCR로 이름·유효기간·문자로 적힌 쿠폰 번호 후보를 채우고 사용자가 검토한다. 쿠폰 번호 표기가 없으면 독립된 8~12자리 영숫자 문자열을 후보로 보되 날짜·전화번호·여러 후보는 확정하지 않는다. QR 코드만 있는 경우와 메모는 직접 입력한다. 직접 입력한 값은 보존하고, 미지원·인식 실패 시 수동 등록을 허용한다. 생성형 AI/외부 분석 서버를 사용하지 않는다.
- 구매일을 만료일로 쓰지 않는다. 명확한 유효기간 표기만 사용하며 서로 다른 만료일 후보가 있으면 빈칸으로 둔다. 날짜가 인식되지 않더라도 원본 이미지 등록은 가능하다.
- 그룹당 사용 상태와 무관하게 최대 100장을 보관한다. 99장에서 두 구성원이 동시에 등록하면 하나만 성공해야 한다. 삭제 처리 중인 이미지는 Storage 정리 완료 전까지 한도에 포함하고, 완전히 삭제하면 다시 등록할 수 있다.
- 같은 그룹에서 목록과 상세를 조회하고 이미지를 확대할 수 있다. 다른 그룹의 ID로 직접 API를 호출해도 조회·수정·이미지 접근은 거부된다.
- 사용 가능 목록은 만료일 가까운 순으로 정렬한다. 날짜 없음은 마지막, 같은 만료일은 최신 등록순이다. 최신 등록순으로 변경할 수도 있다.
- 목록에서 사용 가능한 쿠폰의 남은 일수를 현지 날짜 기준 `D-N`, 당일은 `D-Day`로 표시한다. 7일 이내에는 날짜·아이콘·테두리와 배지를 강조하고, 사용 완료·만료·만료일 없는 쿠폰에는 남은 일수를 표시하지 않는다.
- 미사용·미삭제 쿠폰의 만료 7일 전과 1일 전 한국시간 오전 9시대에 그룹 구성원에게 푸시를 보내고 수신 이력에 남긴다. 동일 쿠폰·만료일·단계는 한 번만 발송한다. 기존 일정 알림 Cron을 재사용한다.
- 만료일 당일까지 사용 가능하며, 다음 날 만료 필터로 이동한다. 사용 완료 쿠폰은 만료 여부와 관계없이 사용 완료 필터에만 포함된다. 전체 필터에는 모두 표시한다.
- 사용 완료 및 취소는 그룹 구성원 모두 가능하고 확인창을 거친다. 이름·쿠폰 번호·메모·만료일 수정과 삭제는 등록자/대표만 가능하다. 동시 수정은 버전 비교로 덮어쓰기를 막는다. 번호가 있으면 상세에 표시한다.
- 쿠폰 상세에서 인증된 이미지를 기기의 사진 보관함에 저장할 수 있다. 저장 중 상태와 성공·실패·권한 거부 안내를 제공하며, 원본이 WebP이면 사진 앱 호환 형식으로 변환한다.
- 사용 완료한 구성원 이름을 목록과 상세에 표시한다. 현재 그룹의 구성원 이름을 사용하며 다른 그룹의 별칭을 가져오지 않는다. 기존 완료 기록도 표시하고, 구성원 탈퇴 등으로 이름이 없으면 안전한 대체 문구를 사용한다. 완료 취소 시 완료자 표시를 없앤다.
- 네트워크 실패 시 등록 화면의 입력을 유지하고 재시도할 수 있다. 실제 기기에서 이미지 선택, QR/바코드 선명도, 두 계정 간 상태 공유를 최종 확인한다.

## 현재 주차 위치 사진 수용 기준

- 대표는 위치 등록 팝업에서 선택적으로 사진을 촬영하거나 보관함에서 고른다. 현재 위치 카드에서는 사진을 보기만 한다. 이미지는 최대 1024px로 축소하고 512KiB까지만 업로드한다.
- 사진은 그룹 구성원에게 현재 위치와 함께 보이고 탭해 확대할 수 있다. 이전 주차 이력에는 사진을 남기지 않는다.
- 차량별 Storage 경로는 하나만 사용한다. 새 위치를 등록하면 이전 사진 연결과 파일을 지운다. 사진 업로드가 실패해도 위치 기록은 유지하고 화면에 별도 오류를 표시한다.

## 홈 위젯·실시간 갱신 수용 기준

- 위젯 백그라운드 동기화는 15분 주기로 요청한다. 정확한 실행 시각은 보장하지 않으며 오늘·내일 일정과 현재 주차 위치를 캐시한다.
- 그룹 데이터 변경 저장 후 무음 푸시를 보내고, 수신 기기는 마지막 선택 그룹이 일치할 때 위젯을 갱신한다.
- 같은 그룹에 로그인한 두 기기에서 한쪽이 일정/주차를 변경하면, 다른 기기는 푸시 수신 후 위젯과 열린 조회 화면을 갱신한다. API와 앱 양쪽 배포 후 실기기로 확인한다.
- 포그라운드 새로고침은 전체 로딩 화면으로 전환하지 않고 현재 탭·선택 날짜·스크롤·작성 중 입력을 보존한다. 다른 그룹의 푸시는 현재 화면에 영향을 주지 않는다.
- 반복 수신은 합쳐 처리하고, 로그아웃 또는 그룹 변경 중 도착한 이전 조회 결과는 위젯에 반영하지 않는다.
- 푸시 지연/누락, 오프라인, 절전, 강제 종료 상태에서는 즉시 갱신을 보장하지 않는다. 네트워크 실패 시 기존 위젯 데이터를 유지한다.
- iOS는 실제 대기 중인 예약을 조회하고, 앱 재실행으로 기존 예약 시각을 계속 뒤로 미루지 않는다. 갱신 엔진 준비 완료 후 서버를 호출한다.
- 설정의 위젯 갱신 화면에서 자동 예약, OS 제한 상태, 실행 시작/서버 조회/위젯 전달 결과를 구분한다. 로그인/그룹 정보 누락과 네이티브 전달 실패를 갱신 성공으로 표시하지 않는다.
