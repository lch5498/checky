# 제품 계획

## MVP 목표

그룹 내 반복 일정과 주차 위치를 빠르게 확인하고 기록하는 작은 내부 앱을 만든다. 첫 화면은 복잡한 대시보드 없이 두 개의 큰 메뉴 버튼만 제공한다.

## 화면

### 홈

- `일정 관리` 버튼
- `주차 관리` 버튼

### 반복 일정 관리

- 이번 주 반복 일정 목록
- 일정 추가: 학생 이름, 반복 일정명, 시작 시간, 종료 시간, 메모
- 일정 수정/삭제
- 다음 단계: 반복 일정, 알림, 캘린더 연동

### 주차 관리

- 현재 주차 위치 보기
- 주차 위치 등록: 차량명, 위치, 주차 시간, 메모
- 이전 주차 기록 보기
- 다음 단계: 사진 첨부, 지도 링크, 위치 공유

## 데이터 모델

- `family_members`: 그룹 구성원
- `academy_events`: 반복 일정
- `parking_records`: 주차 기록

## 기술 방향

- Flutter 앱은 iOS 우선으로 개발한다.
- 앱은 Vercel API만 호출한다.
- Vercel API는 Supabase service role key를 서버에서만 사용한다.
- Supabase Row Level Security는 켜고, 클라이언트 직접 접근은 나중에 인증을 붙일 때 정책을 확장한다.

## 개발 마일스톤

1. 모노레포 생성, Flutter iOS 앱 기본 홈, Vercel API skeleton, Supabase migration
2. 반복 일정 CRUD API와 앱 목록/추가 화면
3. 주차 기록 API와 앱 현재 위치/등록 화면
4. 그룹용 간단 인증 또는 초대 방식 결정
5. iOS TestFlight 배포 준비

## 홈 위젯·실시간 갱신 수용 기준

- 위젯 백그라운드 동기화는 15분 주기로 요청한다. 정확한 실행 시각은 보장하지 않으며 오늘·내일 일정과 현재 주차 위치를 캐시한다.
- 그룹 데이터 변경 저장 후 무음 푸시를 보내고, 수신 기기는 마지막 선택 그룹이 일치할 때 위젯을 갱신한다.
- 같은 그룹에 로그인한 두 기기에서 한쪽이 일정/주차를 변경하면, 다른 기기는 푸시 수신 후 위젯과 열린 조회 화면을 갱신한다. API와 앱 양쪽 배포 후 실기기로 확인한다.
- 포그라운드 새로고침은 전체 로딩 화면으로 전환하지 않고 현재 탭·선택 날짜·스크롤·작성 중 입력을 보존한다. 다른 그룹의 푸시는 현재 화면에 영향을 주지 않는다.
- 반복 수신은 합쳐 처리하고, 로그아웃 또는 그룹 변경 중 도착한 이전 조회 결과는 위젯에 반영하지 않는다.
- 푸시 지연/누락, 오프라인, 절전, 강제 종료 상태에서는 즉시 갱신을 보장하지 않는다. 네트워크 실패 시 기존 위젯 데이터를 유지한다.
- iOS는 실제 대기 중인 예약을 조회하고, 앱 재실행으로 기존 예약 시각을 계속 뒤로 미루지 않는다. 갱신 엔진 준비 완료 후 서버를 호출한다.
- 설정의 위젯 갱신 화면에서 자동 예약, OS 제한 상태, 실행 시작/서버 조회/위젯 전달 결과를 구분한다. 로그인/그룹 정보 누락과 네이티브 전달 실패를 갱신 성공으로 표시하지 않는다.
