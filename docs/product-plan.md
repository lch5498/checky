# 제품 계획

## MVP 목표

그룹 내 반복 일정과 주차 위치를 빠르게 확인하고 기록하는 작은 내부 앱을 만든다. 첫 화면은 복잡한 대시보드 없이 두 개의 큰 메뉴 버튼만 제공한다.

## 화면

### 홈

- `일정 관리` 버튼
- `주차 관리` 버튼

### 반복 일정 관리

- 이번 주 반복 일정 목록
- 일정 추가: 학생 이름, 반복 일정명, 시작 시간, 종료 시간, 메모
- 일정 수정/삭제
- 다음 단계: 반복 일정, 알림, 캘린더 연동

### 주차 관리

- 현재 주차 위치 보기
- 주차 위치 등록: 차량명, 위치, 주차 시간, 메모
- 이전 주차 기록 보기
- 다음 단계: 사진 첨부, 지도 링크, 위치 공유

## 데이터 모델

- `family_members`: 그룹 구성원
- `academy_events`: 반복 일정
- `parking_records`: 주차 기록

## 기술 방향

- Flutter 앱은 iOS 우선으로 개발한다.
- 앱은 Vercel API만 호출한다.
- Vercel API는 Supabase service role key를 서버에서만 사용한다.
- Supabase Row Level Security는 켜고, 클라이언트 직접 접근은 나중에 인증을 붙일 때 정책을 확장한다.

## 그룹 쿠폰 수용 기준

- 사용자는 하단 스크랩의 `글·링크 | 쿠폰` 탭으로 전환한다. 기존 채널/공유 저장 흐름과 하단 홈·일정·주차·스크랩·여행은 유지한다.
- 현재 그룹에 이미지 한 장과 쿠폰 이름을 등록한다. 유효기간·쿠폰 번호·메모는 선택 입력이다. 번호가 없는 QR 쿠폰도 저장할 수 있다. 사진 선택 시 기기 내 OCR로 이름·유효기간·문자로 적힌 쿠폰 번호 후보를 채우고 사용자가 검토한다. 쿠폰 번호 표기가 없으면 독립된 8~12자리 영숫자 문자열을 후보로 보되 날짜·전화번호·여러 후보는 확정하지 않는다. QR 코드만 있는 경우와 메모는 직접 입력한다. 직접 입력한 값은 보존하고, 미지원·인식 실패 시 수동 등록을 허용한다. 생성형 AI/외부 분석 서버를 사용하지 않는다.
- 구매일을 만료일로 쓰지 않는다. 명확한 유효기간 표기만 사용하며 서로 다른 만료일 후보가 있으면 빈칸으로 둔다. 날짜가 인식되지 않더라도 원본 이미지 등록은 가능하다.
- 그룹당 사용 상태와 무관하게 최대 100장을 보관한다. 99장에서 두 구성원이 동시에 등록하면 하나만 성공해야 한다. 삭제 처리 중인 이미지는 Storage 정리 완료 전까지 한도에 포함하고, 완전히 삭제하면 다시 등록할 수 있다.
- 같은 그룹에서 목록과 상세를 조회하고 이미지를 확대할 수 있다. 다른 그룹의 ID로 직접 API를 호출해도 조회·수정·이미지 접근은 거부된다.
- 사용 가능 목록은 만료일 가까운 순으로 정렬한다. 날짜 없음은 마지막, 같은 만료일은 최신 등록순이다. 최신 등록순으로 변경할 수도 있다.
- 목록에서 사용 가능한 쿠폰의 남은 일수를 현지 날짜 기준 `D-N`, 당일은 `D-Day`로 표시한다. 7일 이내에는 날짜·아이콘·테두리와 배지를 강조하고, 사용 완료·만료·만료일 없는 쿠폰에는 남은 일수를 표시하지 않는다.
- 미사용·미삭제 쿠폰의 만료 7일 전과 1일 전 한국시간 오전 9시대에 그룹 구성원에게 푸시를 보내고 수신 이력에 남긴다. 동일 쿠폰·만료일·단계는 한 번만 발송한다. 기존 일정 알림 Cron을 재사용한다.
- 만료일 당일까지 사용 가능하며, 다음 날 만료 필터로 이동한다. 사용 완료 쿠폰은 만료 여부와 관계없이 사용 완료 필터에만 포함된다. 전체 필터에는 모두 표시한다.
- 사용 완료 및 취소는 그룹 구성원 모두 가능하고 확인창을 거친다. 이름·쿠폰 번호·메모·만료일 수정과 삭제는 등록자/대표만 가능하다. 동시 수정은 버전 비교로 덮어쓰기를 막는다. 번호가 있으면 상세에 표시한다.
- 쿠폰 상세에서 인증된 이미지를 기기의 사진 보관함에 저장할 수 있다. 저장 중 상태와 성공·실패·권한 거부 안내를 제공하며, 원본이 WebP이면 사진 앱 호환 형식으로 변환한다.
- 사용 완료한 구성원 이름을 목록과 상세에 표시한다. 현재 그룹의 구성원 이름을 사용하며 다른 그룹의 별칭을 가져오지 않는다. 기존 완료 기록도 표시하고, 구성원 탈퇴 등으로 이름이 없으면 안전한 대체 문구를 사용한다. 완료 취소 시 완료자 표시를 없앤다.
- 네트워크 실패 시 등록 화면의 입력을 유지하고 재시도할 수 있다. 실제 기기에서 이미지 선택, QR/바코드 선명도, 두 계정 간 상태 공유를 최종 확인한다.

## 현재 주차 위치 사진 수용 기준

- 대표는 위치 등록 팝업에서 선택적으로 사진을 촬영하거나 보관함에서 고른다. 현재 위치 카드에서는 사진을 보기만 한다. 이미지는 최대 1024px로 축소하고 512KiB까지만 업로드한다.
- 사진은 그룹 구성원에게 현재 위치와 함께 보이고 탭해 확대할 수 있다. 이전 주차 이력에는 사진을 남기지 않는다.
- 차량별 Storage 경로는 하나만 사용한다. 새 위치를 등록하면 이전 사진 연결과 파일을 지운다. 사진 업로드가 실패해도 위치 기록은 유지하고 화면에 별도 오류를 표시한다.

## 테마·디자인 수용 기준

- 설정 → 화면 설정에서 민트·크림·라벤더·로즈(핑크)·스노우(화이트)를 선택한다. 기본은 민트이며 기존 시스템·라이트·다크 선택은 유지한다.
- 화면 모드와 테마를 별도로 기기에 저장한다. 앱 재시작 시 복원하며 그룹의 다른 구성원에게 영향을 주지 않는다.
- 테마 선택 시 현재 화면과 열린 기존 화면을 즉시 다시 그리되 탭·입력·스크롤은 유지한다.
- 모든 팔레트의 일반 텍스트 및 강조 버튼 텍스트는 4.5:1 이상의 대비를 갖는다. 구성원 색상, 공휴일, 브랜드·원본 이미지는 의미에 따라 유지한다.
- 앱 내 제목·본문·라벨·보조 정보·폼에 공통 스타일을 적용한다. 320pt 화면과 1.3배 글자에서 화면 설정과 대표 목록·폼이 넘치지 않는다.
- 다음 기능은 `docs/design-guide.md`와 디자인 토큰 검사를 따른다.
- 화면 설정 → 글꼴에서 기본·고운돋움·고운바탕·온글잎 박다현체·푸어스토리·인천교육힘찬체를 미리 보고 선택한다. 한글·영문·숫자를 지원하며, 미지원 문자는 시스템 글꼴로 표시한다. 기존 아인맘 선택값은 온글잎 박다현체로 이어지고, 그 외 제외된 글꼴의 기존 저장값은 기본 글꼴로 복원한다.
- 글꼴을 바꾸면 열린 화면의 제목·본문·버튼·입력·피커에 즉시 적용하고 탭·스크롤·작성 중 입력은 보존한다. 테마·화면 모드와 독립적으로 저장하고 재실행 후 복원한다.
- 폰트 TTF와 각 글꼴의 라이선스 원문을 앱에 함께 배포하고 글꼴 화면에서 라이선스를 조회한다. 실행 시 네트워크에서 폰트를 가져오지 않는다.

## 홈 위젯·실시간 갱신 수용 기준

- 앱 홈은 오늘 일정 → 주차 위치 → 만료 예정 쿠폰 → 여행 → 최근 스크랩 순서로 표시한다. 만료 예정 쿠폰은 선택한 그룹의 미사용 쿠폰 중 기기 날짜 기준 D-Day~D-7만 만료일순으로 표시하며, 해당 항목이 없으면 제목·여백을 포함한 섹션 전체를 숨긴다. 🚨 이모지와 D-Day/D-N 표시로 강조하고, 상세 열기·사용 완료·삭제·그룹 전환·홈 복귀·당겨 새로고침·날짜 변경에 반영한다. 쿠폰 조회 실패가 나머지 홈 콘텐츠를 막지 않는다.

- iOS·Android 위젯의 배경·카드·글자·구분선은 앱에서 선택한 테마와 화면 모드를 따른다. 시스템 모드는 OS 밝기를 따르고 구성원 구분색은 유지한다. 테마 변경 시 데이터 재조회 없이 위젯 갱신을 요청하며 주기/푸시 데이터 갱신 후에도 테마가 유지된다. 실제 반영 시각은 OS 정책에 따른다.
- 앱의 글꼴 6종 선택은 iOS·Android 위젯의 제목·시간·구성원·주차·빈 상태에도 적용한다. 글꼴 변경 시 위젯 갱신을 요청하고 재실행·주기/푸시 갱신 후에도 유지한다. 작은/넓은 크기에서 긴 글의 말줄임과 접근성 설명, 탭하여 앱 열기를 유지한다. 알 수 없는 글꼴이나 원본 로딩 실패는 시스템 글꼴로 안전하게 복원한다.
- 위젯 백그라운드 동기화는 15분 주기로 요청한다. 정확한 실행 시각은 보장하지 않으며 오늘·내일 일정과 현재 주차 위치를 캐시한다.
- 그룹 데이터 변경 저장 후 무음 푸시를 보내고, 수신 기기는 마지막 선택 그룹이 일치할 때 위젯을 갱신한다.
- 같은 그룹에 로그인한 두 기기에서 한쪽이 일정/주차를 변경하면, 다른 기기는 푸시 수신 후 위젯과 열린 조회 화면을 갱신한다. API와 앱 양쪽 배포 후 실기기로 확인한다.
- 포그라운드 새로고침은 전체 로딩 화면으로 전환하지 않고 현재 탭·선택 날짜·스크롤·작성 중 입력을 보존한다. 다른 그룹의 푸시는 현재 화면에 영향을 주지 않는다.
- 반복 수신은 합쳐 처리하고, 로그아웃 또는 그룹 변경 중 도착한 이전 조회 결과는 위젯에 반영하지 않는다.
- 푸시 지연/누락, 오프라인, 절전, 강제 종료 상태에서는 즉시 갱신을 보장하지 않는다. 네트워크 실패 시 기존 위젯 데이터를 유지한다.
- iOS는 실제 대기 중인 예약을 조회하고, 앱 재실행으로 기존 예약 시각을 계속 뒤로 미루지 않는다. 갱신 엔진 준비 완료 후 서버를 호출한다.
- 위젯 갱신 진단 화면은 내부 개발·테스트용으로만 유지하고 일반 설정 메뉴에는 노출하지 않는다. 자동 예약과 주기·푸시 갱신은 유지한다. 내부 진단은 로그인/그룹 정보 누락과 네이티브 전달 실패를 갱신 성공으로 표시하지 않는다.

## 통합 검색 수용 기준

### 사용자 시나리오

- "아빠차 지금 어디 있지", "치과 예약 언제였지", "스타벅스 쿠폰 있었나", "제주 여행 때 가기로 한 식당"처럼 기억은 나지만 어느 탭에 있는지 모르는 항목을 찾는다.
- 홈 상단의 검색 버튼 하나로 진입하고, 결과를 누르면 기존 상세 화면으로 바로 이동한다.

### 진입과 입력

- 홈 내비게이션 바 오른쪽, 설정 버튼 왼쪽에 검색 아이콘을 둔다. 그룹을 선택하지 않은 상태에서는 표시하지 않는다.
- 검색 화면은 상단 검색창에 자동 포커스하고, 현재 선택한 그룹 안에서만 검색한다. 그룹 전환은 홈에서 하고 검색 화면에는 그룹 전환을 두지 않는다.
- 공백으로 나눈 모든 단어를 포함하는 항목만 결과로 본다. 대소문자는 구분하지 않고 한글은 부분 일치로 찾는다. 두 글자 미만의 검색어는 서버에 보내지 않고 안내 문구를 보여 준다.
- 입력을 멈춘 뒤 300ms 후에 검색하고, 검색창의 제출 동작으로 즉시 검색할 수 있다. 응답이 늦게 도착한 이전 검색어의 결과는 현재 결과를 덮어쓰지 않는다.
- 검색어를 지우면 결과와 안내를 모두 비운다. 검색 화면을 닫고 다시 열면 이전 검색어를 유지하지 않는다.

### 검색 대상과 결과 표시

| 유형 | 검색 필드 | 결과 한 줄 | 탭 동작 |
| --- | --- | --- | --- |
| 일정 | 제목, 내용, 구성원 이름 | 제목 / 날짜·시간·구성원 | 일정 캘린더를 해당 날짜로 열기 |
| 주차 위치 | 차량명, 차량번호, 위치 문자열(건물·층·상세) | 위치 / 차량·차량번호·주차 시각 | 주차 탭으로 이동 |
| 스크랩 글 | 본문, 링크 제목, 링크 설명, 작성자 이름 | 링크 제목 또는 본문 첫 줄 / 채널·작성자·날짜 | 채널 화면에서 해당 글로 이동 |
| 스크랩 댓글 | 내용, 작성자 이름 | 댓글 내용 / 채널·작성자·날짜 | 채널 화면에서 원글로 이동 |
| 쿠폰 | 이름, 메모, 쿠폰 번호 | 이름 / 만료일·상태(사용 가능·사용 완료·만료) | 쿠폰 상세 |
| 여행 | 여행 제목 | 제목 / 기간 | 여행 상세 |
| 여행 일정 | 제목, 내용 | 제목 / 여행 제목·날짜 | 여행 상세에서 해당 일정으로 이동 |

- 결과는 유형별 섹션으로 묶고 위 표 순서(일정 → 주차 → 스크랩 글·댓글·쿠폰 → 여행·여행 일정)로 보여 준다. 결과가 없는 유형은 섹션을 숨긴다.
- 각 유형은 최대 20개를 보여 주고, 20개를 넘으면 섹션 제목 옆에 `20+`를 표시한다. 쿠폰·스크랩·주차는 작성·주차 시각 내림차순, 여행과 여행 일정은 날짜 내림차순이다.
- 일정은 오늘 23:59:59(기기 시간대)를 기준으로 정렬한다. 기준 시각에서 한 달 뒤까지의 일정을 시작 시각 내림차순(다가오는 한 달 → 오늘 → 과거)으로 먼저 보여 주고, 그보다 먼 미래 일정은 가까운 날짜부터 뒤에 이어 붙인다. 먼 미래 일정이 최근 일정을 밀어내지 않게 하려는 것이다. 20개 제한도 이 순서로 적용한다.
- 반복 일정(교육 프로그램)은 회차가 많아도 프로그램별로 오늘 기준 지난 회차 1건과 다음 회차 1건만 보여 준다. 기념일은 기념일별로 1건만 보여 주며 가장 최근에 지난 날짜를 쓰고, 지난 날짜가 없으면 다가오는 날짜를 쓴다. 단일 일정은 모두 보여 준다.
- 삭제된 쿠폰은 결과에서 제외한다. 사용 완료·만료 쿠폰은 상태를 표시하고 포함한다.
- 구성원 이름(그룹 내 닉네임)으로 검색하면 그 구성원의 일정과 작성한 스크랩 글·댓글이 모두 나온다. 이름이 바뀌면 현재 이름으로 검색된다.
- 주차는 차량별 현재 위치(가장 최근 기록)만 검색한다. 이전 주차 이력은 결과에 넣지 않는다. 차량명이나 차량번호로 검색하면 그 차량의 현재 위치가 나온다.
- 전체 결과가 없으면 "'검색어'에 맞는 항목이 없어요" 빈 상태를 보여 준다. 네트워크 오류는 재시도 버튼과 함께 표시하고 마지막 결과를 지우지 않는다.
- 결과 상세에서 돌아오면 같은 검색어로 다시 검색해 변경을 반영한다. 다른 그룹의 ID로 직접 API를 호출하면 403으로 거부한다.

### API

- `GET /api/mobile/families/{familyId}/search?q=검색어`를 추가한다. 선택 파라미터 `types`(쉼표 구분)로 유형을 제한할 수 있고 기본은 전체다. 선택 파라미터 `anchor`(ISO 8601)는 일정 정렬 기준 시각이며 앱은 기기 기준 오늘 23:59:59를 보낸다. 생략하면 서버 현재 시각을 쓴다.
- 서버는 검색어를 공백으로 나누고 각 단어를 `ILIKE` 패턴으로 이스케이프해 Postgres 함수 `search_family_content`로 한 번에 조회한다. 응답은 `{ query, results: { schedule, coupon, scrap_post, scrap_comment, travel_trip, travel_itinerary, parking } }` 형식이고 각 유형은 `{ items: [], has_more: boolean }`이다. 쿠폰 항목은 쿠폰 목록 API와 같은 형태다.
- 가족 규모 데이터라 별도 검색 인덱스는 두지 않는다. 그룹당 수천 건을 넘기 전까지는 `family_id` 인덱스와 순차 필터로 충분하다.
- 검색 결과는 `ILIKE` 기반 부분 일치다. 형태소 분석, 오타 교정, 관련도 정렬은 범위 밖이며 이후 "체키에게 물어보기"에서 다룬다.

## 브리핑 푸시 수용 기준

### 사용자 시나리오

- 아침에 앱을 열지 않아도 "오늘 뭐 있지"를 푸시 한 통으로 확인한다. 오늘 일정, 차가 어디 있는지, 이번 주 안에 만료되는 쿠폰, 다가오는 여행이 한 화면에 보인다.
- 일요일 저녁에는 선택적으로 다음 주 일정 미리보기를 받는다.
- 생성형 AI 없이 템플릿으로 만든다. 같은 입력이면 항상 같은 문장이 나와야 하며 테스트로 고정한다.

### 설정

- 설정 > 아침 브리핑 화면에서 사용자가 켜고 끈다. 기본은 꺼짐이다. 설정은 사용자 단위이며 기기나 그룹 단위가 아니다.
- 발송 시각은 한국 시간(Asia/Seoul) 기준으로 10분 단위로 고르고 기본은 오전 8:00이다. 서버는 `HH:MM` 형식이면 받아들인다.
- 주간 미리보기는 별도 토글이며 일요일 저녁 8시(한국 시간) 고정이다.
- 변경은 즉시 서버에 저장한다. 저장에 실패하면 이전 값으로 되돌리고 오류와 재시도를 보여 준다.
- 푸시 토큰이 없는 사용자(알림 거부, 로그아웃)는 설정이 켜져 있어도 받지 못한다. 화면에 "기기 알림이 꺼져 있으면 받을 수 없어요" 안내를 둔다.

### 내용

- 아침 브리핑 제목은 `아침 브리핑 · 11/15 (토)` 형식이다. 본문은 사용자가 속한 모든 그룹을 순서대로 담고, 그룹이 둘 이상이면 각 그룹 앞에 `[그룹 이름]` 줄을 넣는다.
- 그룹별 본문 순서는 오늘 일정 → 주차 → 쿠폰 → 여행이다.
  - 오늘 일정: 한국 시간 오늘(00:00~24:00)과 겹치는 일정을 시작 시각순으로 최대 3건. `· 09:00 치과 (민준)`, 종일 일정은 `· 종일 가족 외식`. 4건 이상이면 `· 외 N건`. 없으면 `오늘 일정 없음`.
  - 주차: 차량별 현재 위치를 `주차 아빠차 A동 B2 · 엄마차 B동 B1`처럼 한 줄. 기록이 없으면 줄을 생략한다.
  - 쿠폰: 미사용·미삭제 쿠폰 중 오늘부터 7일 안에 만료되는 것. 1장이면 `쿠폰 스타벅스 11/20 만료`, 여러 장이면 `쿠폰 2장 7일 내 만료 (스타벅스 11/20)`. 없으면 생략.
  - 여행: 아직 끝나지 않은 가장 가까운 여행 하나. 시작 전이면 `제주 여행 D-5`, 당일이면 `제주 여행 D-Day`, 진행 중이면 `제주 여행 2일차`. 없으면 생략.
- 모든 그룹에 보여 줄 것이 없으면 본문은 `오늘은 등록된 일정이 없어요.` 한 줄이다. 설정을 켠 사용자는 내용이 비어도 매일 받는다.
- 주간 미리보기 제목은 `주간 미리보기 · 11/16 (월) ~ 11/22 (일)`이다. 그룹별로 요일별 일정 수(`월 2 · 수 1 · 금 3`), 시작 시각순 일정 최대 3건(`· 11/17 (화) 09:00 치과 (민준)`), 그 주에 겹치는 여행(`제주 여행 11/20 ~ 11/23`), 그 주에 만료되는 쿠폰 수를 담는다. 일정이 없으면 `이번 주 일정 없음`.

### 발송

- 기존 `/api/cron/schedule-alerts` 분기에서 처리한다. 새 Cron job은 필요 없다.
- 매분 실행에서 최근 5분 창(`SCHEDULE_ALERT_LOOKBACK_MINUTES`) 안에 발송 시각이 든 사용자를 찾는다. 자정 근처 창은 전날 날짜도 확인한다.
- `briefing_deliveries`의 `(user_id, briefing_kind, briefing_date)` unique로 하루 한 번만 보낸다. 상태는 `processing`, `sent`, `failed`, `no_targets`(토큰 없음), `empty`(속한 그룹 없음)다.
- 성공한 푸시는 수신 이력에 `briefing_daily`, `briefing_weekly` 유형으로 남긴다. 그룹이 둘 이상이면 첫 그룹에 귀속한다.
- 브리핑 처리 중 오류가 나도 일정·쿠폰 알림 발송은 영향을 받지 않는다.

### API

- `GET /api/mobile/briefing-settings`는 `{ settings: { enabled, sendTime, weeklyPreviewEnabled } }`를 돌려준다. 저장된 설정이 없으면 기본값이다.
- `PUT /api/mobile/briefing-settings`는 같은 세 필드를 부분 갱신한다. `sendTime`은 `HH:MM`이 아니면 400이다.
- 발송 전에 `supabase/migrations/202611150001_add_briefing_settings.sql`을 적용해야 한다.
